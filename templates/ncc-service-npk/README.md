# NCC service npack template

An NCC service package is a signed **metadata** artifact. It tells the node
which container image to run, on which ports, and with which named volumes.
The image itself is built and pushed to a registry exactly as before; npack
only distributes the descriptor and its provenance.

Copy this directory, edit `service.json` and `icon.png`, then build:

```sh
npack-service.py build \
  --service-dir ./hello \
  --version 1.0.0 \
  --publisher npub1... \
  --output ./hello-1.0.0.npk
```

The tool pins `image` to its registry digest before packing. You can pass
`--image ghcr.io/acme/hello:1.0.0` and let it resolve the digest, or replace
the placeholder in `service.json` yourself. Signed packages must use a
digest; a mutable tag is rejected when the package is installed.

Publish it to relays and Blossom:

```sh
npack-service.py publish \
  --manifest ./hello-1.0.0.manifest.json \
  --relay wss://relay.damus.io \
  --server https://blossom.primal.net \
  --secret-key "$NOSTR_SECRET_KEY"
```

Use a dedicated publisher key, not your personal identity. `npack generate-key`
creates one. Clients trust publishers by key, so changing it changes the
package's identity.

## What the fields mean

| Field | Meaning |
| --- | --- |
| `service_id` | NCC service ID and URL segment. Lowercase, hyphens; cannot be reserved. |
| `name` | Display name in the panel. |
| `summary` / `description` | Catalogue listing. 140 and 4000 characters. |
| `categories` | Up to 8 single words, used for filtering. |
| `homepage` / `license` / `support_url` | Listing links and licence. |
| `icon` | PNG or SVG in this directory, at most 256 KiB. Published as a Blossom blob. |
| `compose_service` | Compose service key. Must be unique in the bundle. |
| `image` | `registry/repository@sha256:<digest>`. |
| `public_port` | Public TLS port Caddy listens on. Must be free and not reserved. |
| `backend_port` | Loopback port for the container. Not published. |
| `container_port` | Port the process listens on inside the container. |
| `probe_path` | HTTP path used to decide the service is up. |
| `env` | Optional environment variables. |
| `volumes` | Optional named volumes, mapped to absolute container paths. |
| `min_bundle_version` | Optional NCC Server version this package expects. |

The Compose fragment is generated by NCC Server, not shipped in the package.
It pins the image, publishes only `127.0.0.1:<backend_port>`, sets
`read_only`, drops all capabilities, sets `no-new-privileges`, and mounts only
the named volumes you declare. Packages cannot request host networking, extra
capabilities, devices, bind mounts or a Docker socket.

Installing a package creates the usual NCC service record, a Caddy TLS
listener on `public_port`, and its own Tor onion endpoint:

```sh
sudo make service-install REF=npub1.../hello@1.0.0
```

The node verifies the release event, the artifact SHA-256, and the descriptor
before it writes anything.
