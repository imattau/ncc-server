# Build an NCC service

This is the developer quickstart for running your application as an NCC service
on an NCC-Server node. It covers the container contract, a working example,
local validation, installation, signed distribution, upgrades, and removal.

There are two installation routes:

| Route | Use it for | Install command |
| --- | --- | --- |
| Operator-authored Compose package | Your own node, local experiments, private apps | `sudo make service-add PACKAGE=./hello` |
| Signed npack package | Distributing the service to other nodes | `sudo make service-install REF=npub.../hello@1.0.0` |

Both routes use the same service descriptor and the same runtime integration:
the sidecar record, Caddy TLS listener, Tor onion, NCC locator, and the panel's
Installed page.

## Container contract

Your image must:

- listen on `0.0.0.0:<container_port>`; do not bind the container to
  `127.0.0.1`
- serve plain HTTP on that one port; Caddy terminates TLS
- run as a non-root user
- tolerate a read-only root filesystem
- write only to `/tmp` or to named volumes declared in the descriptor
- expose one HTTP health path, for example `/healthz`
- be readable from the node without credentials; the node pulls images
  anonymously
- be published for the node's architecture, or as a multi-arch image

NCC services have one HTTP backend port and one public TLS port. They cannot
request host networking, extra capabilities, devices, bind mounts, a Docker
socket, or a custom Caddy fragment.

## Quickstart

From the `ncc-server` checkout:

```sh
make service-new NAME=hello DIR=./hello IMAGE=ghcr.io/acme/hello:latest
```

This copies the working example in `examples/hello-service` and fills in the
service id, display name, image, and ports. It creates:

```text
hello/
├── Dockerfile
├── server.mjs
├── compose.yaml
├── service.json
├── icon.svg
├── README.md
├── .dockerignore
└── .github/workflows/publish.yml
```

Replace `server.mjs` and `Dockerfile` with your application. Keep the
`service.json` contract aligned with the container.

Run it locally:

```sh
make service-build PACKAGE=./hello IMAGE=hello-service:dev
docker run --rm --read-only --tmpfs /tmp -p 127.0.0.1:18080:8080 hello-service:dev
curl http://127.0.0.1:18080/healthz
```

## Validate before installing

```sh
make service-check PACKAGE=./hello
```

The checker validates the descriptor, reserved ports, the image/digest rules,
the Compose mapping, and common sandbox mistakes such as `privileged: true`,
host networking, a Docker socket mount, or a host bind mount. It runs without
root and without a running node.

Useful variants:

```sh
make service-check PACKAGE=./hello SIGNED=1      # require @sha256: digest
make service-check PACKAGE=./hello ONLINE=1      # also ask the registry
make service-check PACKAGE=./hello JSON=1        # machine-readable output
```

Preview an install without changing anything:

```sh
sudo make service-add PACKAGE=./hello DRY_RUN=1
```

## Install on your node

Build and push the image first. It must be public, or the host must already
have registry credentials:

```sh
make service-build PACKAGE=./hello IMAGE=ghcr.io/acme/hello:1.0.0 PUSH=1
```

Then, on the node:

```sh
sudo make service-add PACKAGE=/path/to/hello
```

The installer pulls the image, starts the container, waits for `/healthz`,
creates the sidecar record, writes the Caddy listener, adds a Tor onion, and
publishes the locator. The service is available at
`ncc://<operator-npub>/hello/`.

The public TLS port must be open in the host firewall and forwarded by the
router if the service should be reachable from the internet. The loopback
backend port must not be exposed.

## Publish a signed package

A signed package lets other nodes discover and install the service. The image
stays in its registry; npack distributes the signed descriptor.

```sh
python3 /path/to/ncc-server/scripts/npack-service.py build \
  --service-dir ./hello \
  --version 1.0.0 \
  --publisher npub1... \
  --image ghcr.io/acme/hello:1.0.0 \
  --output ./hello-1.0.0.npk

python3 /path/to/ncc-server/scripts/npack-service.py publish \
  --manifest ./hello-1.0.0.manifest.json \
  --secret-key "$NOSTR_SECRET_KEY" \
  --relay wss://relay.damus.io \
  --server https://blossom.primal.net
```

Install it on a node with:

```sh
sudo make service-install REF=npub.../hello@1.0.0
```

The node verifies the release signature, artifact hash, and descriptor before
it writes anything. The Compose fragment is generated by the node, not supplied
by the publisher.

### Build and publish from your repository

The example repository workflow in
`examples/hello-service/.github/workflows/publish.yml` builds the image,
pushes it to GHCR, and calls the reusable packaging workflow.

Set these in the service repository:

- variable `NCC_PUBLISHER` — the publisher npub
- secret `NOSTR_SECRET_KEY` — the publisher secret key

The image workflow is reusable and can be called directly:

```yaml
jobs:
  build:
    uses: imattau/ncc-server/.github/workflows/build-service-image.yml@v0.2.31
    with:
      image: ghcr.io/acme/hello-service
      tag: 1.0.0
    permissions:
      contents: read
      packages: write
```

Then pass `${{ needs.build.outputs.image }}@${{ needs.build.outputs.digest }}`
to `publish-service-package.yml`.

Notes:

- GHCR packages are private by default. Make the package public after its first
  publish, or configure host credentials.
- The workflow pins the pushed digest in the descriptor.
- `repo` in the npack manifest is provenance metadata. It is not used to clone
  or build anything.

## Upgrade, roll back, remove

```sh
sudo make service-upgrade PACKAGE=/path/to/hello
sudo make service-rollback SERVICE=hello
sudo make service-remove SERVICE=hello
```

`service-upgrade` keeps the previous package under
`custom-services/packages/.previous/<service-id>`. If the new container does not
become healthy, the installer attempts to restore the previous package and
container.

`service-remove` stops and removes the container, removes the Caddy route and
sidecar record, and best-effort removes the Tor onion. Named volumes are kept
unless you pass `PURGE=1`:

```sh
sudo make service-remove SERVICE=hello PURGE=1
```

The last published locator remains on relays until its TTL expires.

## Troubleshooting

- **The container exits with a read-only filesystem error.** The image writes
  outside `/tmp`. Use an image that writes only `/tmp`, or mount writable
  directories as tmpfs or named volumes.
- **The backend probe times out.** The image is not listening on
  `0.0.0.0:<container_port>`, or `probe_path` is wrong.
- **The node cannot pull the image.** The package is private, the tag does not
  exist, or the node's architecture is not in the image manifest.
- **`compose_service` is already used.** Every installed package needs a unique
  Compose service key. `make service-new` derives `<service-id>-app`.
- **The panel shows the service under its id.** The display name comes from the
  service record; check `name` in `service.json`.
- **Caddy does not serve the new port.** Open the port in the firewall and
  reload/recreate Caddy if the route was written manually.
