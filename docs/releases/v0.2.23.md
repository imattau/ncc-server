# v0.2.23

## Private services with encrypted locators

Services can now keep their endpoint out of public NCC records. A private
service publishes its NCC-02 anchor without a `u` endpoint and an NCC-05
locator encrypted with NIP-44 to the operator, node admins and any extra
recipient keys. Relays still see the record exists and when it changed, but
only a recipient key can decrypt the address.

- `make service-private SERVICE=… RECIPIENTS="npub1…"` and
  `make service-public SERVICE=…`
- `make service-list` shows each service's visibility and recipient count
- `PRIVATE=1` / `RECIPIENTS=` / `NO_ADMINS=1` for custom package installs
- `NCC_PRIVATE_SERVICES` and `NCC_PRIVATE_RECIPIENTS` in `.env` for repeatable
  provisioning
- the admin panel's **Installed → Access** dialog switches visibility, manages
  recipients and republishes through a NIP-98-authorized sidecar route
- re-provisioning preserves an existing private setting instead of silently
  republishing a service

Multi-recipient private services use the wrapped NCC-05 form. NCC Browser now
decrypts that form as well as the single-recipient form.

`ncc-search` continues to refuse decryption and now removes private services
from its index instead of listing them as unreachable public entries.

Private is unlisting, not access control: the service port remains reachable.
Use the service's own login or a firewall when the content must be protected.
See [`docs/private-services.md`](../private-services.md).

## Upgrading

```sh
cd /opt/ncc-server
sudo make bundle-upgrade REF=v0.2.23
```

or use **Upgrade to v0.2.23** on the admin panel's Overview page. If you pin
images yourself, move the `ghcr.io/imattau/ncc-server-*` pins to `:0.2.23`.

After the upgrade, the sidecar image includes the new visibility route. Run
`sudo make bundle-provision-services` only if you need to create a missing
service record; existing visibility is preserved.
