# v0.2.29

## NCC links in posts

A standalone `ncc://<npub>/<service>` link in a post, quote, or embedded note
now renders an NCC service card. The card reads the service's public kind
`30059` anchor and shows:

- the service name and shortened `ncc://` address,
- `Public`, `Private`, or `Expired`,
- the public endpoint host when the anchor publishes one.

It does not contact the service endpoint. Inside NCC Browser the card offers
**Open**; in an ordinary browser it offers **Copy address**. If the service
record is not on the configured relays, the card falls back to the address
alone.

This is not an OpenGraph preview: title, description, and image need a later
NCC Browser preview endpoint that resolves the service page.

## Ditto web integration branch

The `ncc-server-ditto-web` image is now pinned to the fork's `ncc-web`
integration branch. That branch carries the NCC web changes in source:

- `ncc://` and `nsite://` profile links,
- the mobile nsite handoff,
- the new NCC post cards.

The separate profile-link build patch has been removed. Only the router,
referrer, fetch-compatibility and sync-timeout compatibility patches remain.

Only the `ncc-server-ditto-web` image changed. The other component images are
rebuilt and published under the same tag.

## Upgrading

```sh
cd /opt/ncc-server
sudo make bundle-upgrade REF=v0.2.29
```

or use **Upgrade to v0.2.29** on the admin panel's Overview page. If you pin
images yourself, move `ghcr.io/imattau/ncc-server-ditto-web` to `:0.2.29`.

## Verifying

1. Publish a post containing a public `ncc://<npub>/<service>` address on its
   own line. The post should show the service card.
2. In NCC Browser, **Open** should open the service.
3. In an ordinary browser, **Copy address** should copy the canonical
   `ncc://` address.
4. A private service should show `Private` and no endpoint host.
5. Confirm the profile website `ncc://` and `nsite://` links still work on
   desktop and mobile.
