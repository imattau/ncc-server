# v0.2.31

This release stops the sidecar from publishing a new kind 0 profile on every
locator refresh. Routine cadence ticks now leave the profile alone, so relays
and clients stop showing regular profile updates when nothing changed.

## Fixes

- A kind 0 is published only when the public profile actually changes, on the
  first publish, or on an explicit republish. The default 30-minute relay and
  6-hour service cadence previously attached a new profile event to every
  expiring NCC-05 locator refresh.
- `display_name` and `nip05` are now part of the profile change hash. Editing
  either from the panel or a service config publishes the profile; the old
  hash only covered `name`, `about` and `picture`.
- The admin panel docs describe the kind 0 lifecycle and note that cadence
  refreshes cover anchors and locators, not the profile.

The sidecar image carries the change as
`patches/ncc-sidecar-profile-publish.patch`; no host, Caddy or data migration
is needed.

## Verify

- Edit **Settings → Public identity**, save, and confirm a `Kind 0` publish in
  the sidecar log within about a minute.
- Leave the node running past the relay refresh interval and confirm
  `Published updates … (Interval)` lists only NCC-02/NCC-05, not `Kind 0`.
- The first cycle after upgrading may publish the profile once per service
  because the hash format changed. After that, cadence refreshes stay quiet.

Upgrade as usual:

```sh
cd /opt/ncc-server
sudo make bundle-upgrade REF=v0.2.31
```
