# v0.2.27

## Optional public HTTPS domains

Each Installed card can now have one optional public HTTPS domain, such as
`https://ditto.example.com`, configured from the admin panel's
**Installed → Domain** action. The domain is a standard front door only: Caddy
terminates TLS and reverse-proxies it to the service. NCC service records,
locators, endpoint ordering and certificate pins do not change, and saving or
removing a domain never triggers a publish cycle.

The node-agent renders the configured domains into
`custom-services/caddy/50-ncc-public-domains.caddy` and reloads Caddy. The
generated file is gitignored and survives ordinary container restarts. The
sidecar reapplies it on startup and every five minutes, so a deleted file or a
removed service is reconciled automatically.

Supported services are `web`, `addr`, `admin`, `ditto`, `search`, `relay`, and
custom services with a loopback `health_url` or `probe_url`. `npanel` is
deliberately excluded: its dashboard and NIP-98 origin are bound to one
`dashboard_host`, so a second domain would break the existing address unless
npanel itself is reconfigured.

The operator still has to point the domain's A/AAAA record at `PUBLIC_IPV4` and
allow TCP 80 and 443 through the host firewall and router. Caddy obtains and
renews the certificate automatically; issuance runs in the background after
the domain is saved. A private service can have a domain, but the dialog warns
that the domain makes the service publicly reachable even though its locator
stays private.

This feature is available only in the Compose bundle, where the node-agent can
write and reload the Caddy fragment. A native systemd install would need a
separate host-side writer and reload helper.

## Upgrading

```sh
cd /opt/ncc-server
sudo make bundle-upgrade REF=v0.2.27
```

or use **Upgrade to v0.2.27** on the admin panel's Overview page. If you pin
images yourself, move the `ghcr.io/imattau/ncc-server-*` pins to `:0.2.27`.

The sidecar image (which also runs the node-agent) and the caddy-panel image
must both be upgraded for the domain action and the generated Caddy import.
Other component images can be upgraded as usual.

## Verifying

1. Point a domain's A/AAAA record at `PUBLIC_IPV4` and allow TCP 80 and 443.
2. On **Installed**, open **Domain** for a supported service, enter the domain
   and save.
3. Check that
   `custom-services/caddy/50-ncc-public-domains.caddy` contains the domain and
   that `https://<domain>/` loads after certificate issuance completes.
4. Confirm the service's existing `ncc://` address and pinned HTTPS listener
   still work unchanged.
