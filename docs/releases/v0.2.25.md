# v0.2.25

## Dedicated npubs for services

A service can now publish its NCC records under its own key instead of the
node operator's key. The change is opt-in per service.

- **Installed → New npub** creates a key for one service, retires the old
  address and republishes under the new key.
- **Installed → Access** has **Create a new npub for this service**, so a
  public-to-private change can also move the service in the same publish
  cycle.
- `make service-rekey SERVICE=search` is the CLI equivalent.
- `make service-private SERVICE=search NEW_IDENTITY=1 RECIPIENTS="npub1…"`
  combines identity and visibility.

The service address changes from `ncc://<operator>/<service>/` to
`ncc://<new-npub>/<service>/`, so existing links must be re-shared. By default
the old locator is expired and its anchor is republished without an endpoint
and marked private, which also removes the old row from ncc-search. This can be
disabled with `NO_RETIRE=1` or the panel checkbox.

The `addr` service is deliberately excluded: changing it would break the bare
`ncc://<operator>/` root address.

Dedicated keys are stored in `sidecar.db`. Re-provisioning, custom-package
reinstalls and operator-identity migration preserve them. The operator and
admin keys remain the management keys and remain recipients for private
services.

## Panel and API

- `GET /ncc-api/services` now includes each service's `npub` and
  `shared`/`dedicated` identity mode.
- `POST /ncc-api/services/<id>/identity` rotates one service key.
- `PUT /ncc-api/services/<id>/visibility` accepts `newIdentity` and
  `retireOld`.
- `GET /ncc-api/records` queries every service author, not only the operator.
- The Installed card shows a dedicated npub and the new action; Overview opens
  the dedicated address in both places.

## Upgrading

```sh
cd /opt/ncc-server
sudo make bundle-upgrade REF=v0.2.25
```

or use **Upgrade to v0.2.25** on the admin panel's Overview page. If you pin
images yourself, move the `ghcr.io/imattau/ncc-server-*` pins to `:0.2.25`.

The sidecar image must be upgraded for the new identity route and card control.
Existing services keep the operator identity until changed.
