# v0.2.28

## nsite profile links stay native on mobile

On mobile, Nostr Navigator serves NCC pages through a loopback proxy
(`http://<pubkey>.<service>.localhost:<port>`) instead of loading an `ncc://`
origin. Ditto previously decided whether it was inside NCC Browser by checking
`window.location.protocol === 'ncc:'` alone, so on mobile it opened its own
nsite viewer and left the address bar on the Ditto `ncc://` address.

Ditto now also recognises the mobile proxy host and the `NostrNavigator/<version>`
user agent. An nsite link clicked in Ditto on mobile is handed to the browser,
which opens `nsite://…` natively, the same as on desktop. Snapshots still open in
Ditto's viewer because NCC Browser cannot parse the snapshot address form.

Only the `ncc-server-ditto-web` image changed. The other component images are
rebuilt and published under the same tag.

## Upgrading

```sh
cd /opt/ncc-server
sudo make bundle-upgrade REF=v0.2.28
```

or use **Upgrade to v0.2.28** on the admin panel's Overview page. If you pin
images yourself, move `ghcr.io/imattau/ncc-server-ditto-web` to `:0.2.28`.

## Verifying

1. On mobile, open Ditto in Nostr Navigator and visit a profile whose website
   is an `nsite://` address.
2. Tap the nsite link. The address bar should show `nsite://…`, not the Ditto
   `ncc://` route.
3. On desktop, confirm the link still opens `nsite://…` natively.
4. In an ordinary browser, confirm the link still opens Ditto's nsite viewer.
