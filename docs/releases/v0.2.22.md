# v0.2.22

## Upgrades no longer blocked by the host's Docker CLI

Before changing anything, the server upgrade checks that every image for the
target release is published. That check used `docker manifest inspect`, which
runs in the Docker CLI's own network and credential context rather than the
daemon's. On some hosts it reports a live release as missing, so **Upgrade to
vX.Y.Z** in the admin panel and `make bundle-upgrade` failed with "The images
for this release are not published yet" even though the images were public.

The runner now:

- retries an image check with an empty Docker config when the host's saved
  GHCR login cannot see a public image;
- asks GHCR directly over HTTPS when the Docker CLI still cannot confirm a
  manifest, so a CLI/daemon proxy or network difference no longer blocks the
  upgrade;
- says whether the image is missing or the registry could not be checked from
  this host, instead of blaming the release;
- accepts `NCC_UPGRADE_SKIP_IMAGE_CHECK=1` to skip the check and let the
  pull/recreate decide. A genuinely missing image still fails there with
  `manifest unknown`.

There are no new adapters or database changes in this release; it is the
upgrade path itself that changed.

## Upgrading

Normal upgrade, no manual steps on a host whose check works:

```sh
cd /opt/ncc-server
sudo make bundle-upgrade REF=v0.2.22
```

or use **Upgrade to v0.2.22** on the admin panel's Overview page. If you pin
images yourself, move the `ghcr.io/imattau/ncc-server-*` pins to `:0.2.22`.

**One-time note for installs older than v0.2.22:** the runner performing this
hop is the one already installed, so it still has the old check. If that host
cannot see GHCR with its Docker CLI, run the fixed runner once:

```sh
cd /opt/ncc-server
sudo git fetch origin main
sudo git show FETCH_HEAD:scripts/upgrade-compose-host.py > /tmp/upgrade-compose-host.py
sudo python3 /tmp/upgrade-compose-host.py --project-dir /opt/ncc-server --manual --target v0.2.22
```

or let the already-installed runner skip the check:

```sh
sudo env NCC_UPGRADE_SKIP_IMAGE_CHECK=1 python3 ./scripts/upgrade-compose-host.py --manual --target v0.2.22
```

Once v0.2.22 is installed, later upgrades use the fixed check automatically.

## Verifying

1. The admin panel offers **Upgrade to v0.2.22** and completes, or
   `make bundle-upgrade REF=v0.2.22` exits cleanly.
2. `make bundle-health` and the panel's service list stay healthy.
3. A later upgrade no longer needs the one-time command above.
