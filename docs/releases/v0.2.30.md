# v0.2.30

This release makes it practical to build and run an application as an NCC
service without reverse-engineering the bundle.

## Build an NCC service

- New [Build an NCC service](https://github.com/imattau/ncc-server/blob/main/docs/build-a-service.md) guide covering the container
  contract, local validation, installation, signed publishing, upgrades,
  rollback, and removal.
- New `examples/hello-service`: a working, zero-dependency Node service with a
  Dockerfile, Compose package, signed-package workflow, and `/healthz` probe.
- New `make service-new NAME=...` scaffold command creates a service package
  from the example and fills in the service id, image, and ports.
- New `make service-check PACKAGE=...` validates a package without root, Docker,
  a sidecar, or an installed node.
- New `make service-build PACKAGE=... IMAGE=...` builds an image locally.
- New reusable `build-service-image.yml` workflow builds and pushes an image
  from the service repository, with an image digest output for packaging.
- `make service-add` and `make service-install` accept `DRY_RUN=1`.
- `healthcheck_path` is now used for the sidecar health URL, separate from the
  install probe path.

## Service lifecycle

- New `make service-upgrade PACKAGE=...` and `REF=...` flow. The previous
  package is kept under `custom-services/packages/.previous/<service-id>`.
- New `make service-rollback SERVICE=...`.
- New `make service-remove SERVICE=...`; named volumes are kept unless
  `PURGE=1`.
- Local Compose edits are refreshed on reinstall instead of being silently
  ignored.
- A failed upgrade attempts to restore the previous package, container, and
  Caddy route.

## Fixes

- The custom Compose template now starts with its own sandbox settings. It uses
  `nginxinc/nginx-unprivileged` on port 8080 with the writable directory under
  `/tmp`, instead of failing on a read-only `/var/cache/nginx`.
- The panel says **Review package** and **Copy install command** instead of
  implying that it installs packages itself.
- Custom services are labelled with their descriptor `name` in the panel.
- The Apps page links to the developer quickstart.
- Installed cards offer a copyable `make service-remove` command.
- Corrected the Tor and update statements in the custom-service docs.

Upgrade as usual:

```sh
cd /opt/ncc-server
sudo make bundle-upgrade REF=v0.2.30
```
